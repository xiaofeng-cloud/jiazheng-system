# 项目需求分析

## 1. 项目背景

家政服务业务通常同时面对客户、服务人员和平台调度人员。需求信息分散、派单依赖人工经验、服务过程缺少时间线、评价和投诉无法形成闭环，都会影响服务质量。本系统面向中国大陆家政服务企业，使用纯 Web 前后端分离方式，把一次服务从需求提交追踪到评价和投诉处理。

## 2. 建设目标

系统以“需求提交—审核—调度—接单—服务—验收—评价—投诉—统计”为主线，提供可审计的工单状态、可解释的人员匹配和基于 MySQL 实时查询的质量指标。系统不处理资金流转，便于本科毕业设计演示和后续扩展。

## 3. 角色需求

| 角色 | 主要权限 |
| --- | --- |
| 客户 | 注册登录、浏览项目、维护地址、提交需求、查看本人工单、验收评价、投诉反馈 |
| 家政服务人员 | 查看本人派单、接单或拒单、记录服务过程、上传图片元数据、维护工作状态 |
| 系统管理员/调度员 | 管理用户和项目、审核需求、候选人员分析、派单转派、质量监督、公告、日志和统计 |

后端权限是最终安全边界，前端菜单隐藏只用于改善操作体验。客户按 `customer_id` 限制数据范围，服务人员按 `provider_id` 限制工单范围。

## 4. 非功能需求

- 使用 Java 17、Spring Boot 3、MySQL 8.0、Vue 3 和 Element Plus。
- 所有页面、注释、数据库说明和接口文档使用简体中文。
- 密码使用 BCrypt，接口使用 JWT 无状态认证，关键操作写入历史或操作日志。
- 测试数据全部为虚构的中国大陆姓名、电话、地址和证件号。
- 不开发微信小程序、APP、在线支付、充值、退款、押金、交易、钱包、提现或服务商结算功能。
