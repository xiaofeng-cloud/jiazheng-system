# 系统功能设计

## 1. 功能分层

```mermaid
flowchart LR
  A[客户] --> B[服务项目与地址]
  B --> C[服务需求]
  C --> D[需求审核]
  D --> E[工单状态机]
  E --> F[人员调度]
  F --> G[服务过程]
  G --> H[客户验收评价]
  H --> I[投诉与质量监督]
  I --> J[统计分析]
```

## 2. 业务模块

用户权限模块负责注册、登录、角色和账号状态；基础资料模块维护服务分类、项目、区域、客户地址和服务人员档案；工单模块维护需求、审核、派单、接单、状态历史和取消；过程模块维护签到、开始、服务中、完成及图片元数据；质量模块维护验收、评价、投诉、处理记录；系统模块维护公告、操作日志和看板统计。

## 3. 工单状态规则

`待审核 → 待分配 → 待接单 → 已接单 → 服务中 → 待确认 → 已完成`。客户可以在待审核、待分配、待接单阶段取消；服务人员拒单会回到待分配；管理员派单时检查服务人员状态、预约时间冲突和当前负载。状态变化只能通过后端状态服务，不能使用普通字段更新绕过校验。

## 4. 质量闭环

服务人员提交完成过程后，工单进入待确认；客户验收后进入已完成，只有已完成工单可以评价；投诉必须关联原工单，管理员处理时写入投诉处理记录。统计接口返回工单状态分布、趋势、完成数、平均评分和待处理投诉数，空数据返回零值或空数组。
