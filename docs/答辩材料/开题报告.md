## 一、研究背景与意义

家政服务订单涉及客户需求、服务人员能力、时间和区域等多种约束。传统人工登记容易造成信息遗漏、派单不透明和售后处理缺少证据。本课题通过 Web 信息系统保存需求、工单状态、调度原因、服务时间线、验收评价和投诉记录，为企业提供统一的过程管理工具，也为服务质量分析提供数据基础。

## 二、研究内容

系统设置客户、家政服务人员、系统管理员三类角色，实现用户权限、服务项目、区域和地址、服务需求、工单审核与状态流转、人员调度、服务过程、验收评价、投诉处理、通知、日志和统计分析模块。调度采用技能、区域、工作状态、时间冲突和当前负载的可解释规则。系统使用 Vue3 + Element Plus 前端、SpringBoot + Spring Security + JWT 后端、MySQL + MyBatis-Plus 数据持久化和 ECharts 统计展示。

## 三、技术路线

采用前后端分离架构，浏览器通过 Axios 调用 REST 接口；后端按 Controller、Service、Mapper 分层，状态机统一校验工单变化，事务保证审核生成工单、派单和验收的一致性；数据库使用外键和索引维护关联；测试使用 JUnit、Spring Boot Test 和 H2 验证核心规则。

## 四、重点与难点

重点是工单状态机和角色数据范围控制；难点是同时满足技能、区域、时间和负载的调度条件，以及让评价和投诉能追溯到原工单。解决方式是把状态转换集中到领域服务，把调度结果和原因保存为记录，并用操作日志和状态历史形成审计链。

## 五、预期成果

完成可本地运行的前后端项目、MySQL 建表与初始化脚本、三角色登录和权限控制、核心业务接口、中文操作界面、统计看板、测试记录、部署说明和答辩材料。系统明确排除微信小程序、在线支付、充值、退款、押金、交易、钱包、提现和结算功能。
