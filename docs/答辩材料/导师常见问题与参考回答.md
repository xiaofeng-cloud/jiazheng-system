# 导师常见问题与参考回答

## 1. 为什么选择这个题目？

家政服务具有需求多样、时间和区域约束明显、服务质量需要留痕的特点，适合体现数据库设计、权限控制、状态机和前后端协同能力，工作量也符合本科毕业设计。

## 2. 调度算法是否使用人工智能？

没有使用复杂人工智能。系统采用可解释的业务规则，依次检查技能、区域、工作状态、预约时间冲突和当前负载，并把匹配原因保存到调度记录，便于管理员理解和改派。

## 3. 如何防止越权？

Spring Security 过滤 JWT 并恢复用户身份，Controller 使用角色注解，Service 再检查客户地址、工单客户或服务人员归属。前端隐藏菜单只是交互优化，不是安全措施。

## 4. 如何保证工单状态正确？

所有状态变化进入 `WorkOrderStatusService`，只允许预先定义的边；审核、派单、接单、服务、验收和取消分别写入状态历史，普通更新接口不能直接改状态。

## 5. 如何保证统计真实？

统计接口直接查询 MySQL 的工单、评价和投诉表，前端通过 Axios 请求接口。没有数据时返回零值和空数组，页面显示暂无统计数据，不使用业务静态数组。

## 6. 项目有哪些边界？

项目只管理服务需求、工单调度和质量追踪，不涉及在线支付、充值、退款、押金、交易、钱包、提现和服务商结算。
