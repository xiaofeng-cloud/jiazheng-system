# REST 接口文档

## 1. 通用约定

- 基础路径：`/api`；请求和响应使用 UTF-8 JSON。
- 登录接口和注册接口无需令牌，其余接口在请求头携带 `Authorization: Bearer <JWT>`。
- 统一响应：`{"code":200,"message":"操作成功","data":{}}`；参数错误 400、业务冲突 409、服务器错误 500。

## 2. 认证与资料

| 方法 | 路径 | 权限 | 说明 |
| --- | --- | --- | --- |
| POST | `/auth/register` | 公开 | 注册客户账号 |
| POST | `/auth/login` | 公开 | 登录并签发 JWT |
| GET | `/auth/me` | 登录 | 当前用户 |
| POST | `/auth/logout` | 登录 | 客户端清理令牌 |
| GET/POST | `/service-items` | 登录/管理员 | 查询或新增服务项目 |
| GET | `/regions` | 登录 | 查询启用区域 |
| GET/POST | `/customer/addresses` | 客户 | 查询或新增本人地址 |
| GET/PUT | `/providers`、`/providers/me/status` | 登录/服务人员 | 查询档案和工作状态 |

## 3. 业务闭环

| 方法 | 路径 | 权限 | 说明 |
| --- | --- | --- | --- |
| GET/POST | `/demands` | 登录/客户 | 查询或提交需求 |
| POST | `/demands/{id}/approve` | 管理员 | 审核并生成工单 |
| GET | `/work-orders` | 登录 | 按角色返回可见工单 |
| PUT | `/work-orders/{id}/status` | 三角色 | 执行合法状态转换 |
| POST | `/work-orders/{id}/accept`、`/reject`、`/cancel` | 对应角色 | 接单、拒单、客户取消 |
| GET/POST | `/scheduling/orders/{id}/candidates`、`/assign` | 管理员 | 候选人员和派单 |
| GET/POST | `/service-process/orders/{id}` | 登录/服务人员 | 时间线和过程记录 |
| POST | `/reviews/orders/{id}/accept`、`/reviews/orders/{id}` | 客户 | 验收和评价 |
| GET/POST/PUT | `/complaints` | 对应角色 | 投诉、查看和处理 |
| GET | `/statistics/dashboard` | 管理员 | ECharts 看板数据 |

## 4. 状态请求示例

```json
{"status":"IN_SERVICE","remark":"服务人员已到达并开始服务"}
```
