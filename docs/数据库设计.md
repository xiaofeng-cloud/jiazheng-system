# 数据库初步设计

数据库名称为 `jiazheng_system`，采用 MySQL 8.0 和 `utf8mb4`。主键统一使用 `BIGINT`，业务编号使用可读字符串，用户密码只保存 BCrypt 摘要。工单状态变化写入独立历史表，便于审计和质量追踪。

| 分组 | 数据表 | 用途 |
| --- | --- | --- |
| 权限 | `sys_user`、`sys_role`、`sys_menu`、关联表 | 用户、角色和菜单权限 |
| 服务基础 | `service_category`、`service_item`、`service_region` | 服务分类、项目、区域 |
| 参与者 | `customer_profile`、`provider_profile`、`provider_skill`、`customer_address` | 客户地址和服务人员能力 |
| 业务 | `service_demand`、`work_order`、`work_order_assignment` | 需求、工单和调度记录 |
| 质量 | `work_order_status_log`、`service_process`、`service_image`、`service_review` | 状态、过程、图片和评价 |
| 闭环 | `complaint`、`complaint_record`、`sys_notice` | 投诉处理、通知 |
| 审计 | `login_log`、`operation_log`、`sys_config` | 登录、操作和系统配置 |

工单状态采用 `待审核 → 待分配 → 待接单 → 已接单 → 服务中 → 待确认 → 已完成` 主流程，异常场景进入 `已取消`。后端服务层负责校验状态转移，任何转移都写入 `work_order_status_log`。

初始化脚本包含 30 个客户、20 名服务人员、10 个服务项目、8 个服务区域、100 条服务需求、100 条工单、50 条调度记录、100 条过程记录、60 条评价、15 条投诉和 10 条通知，均为虚构数据。
