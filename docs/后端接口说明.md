# 后端接口说明（当前阶段）

后端统一使用 `/api` 前缀，登录后在请求头携带 `Authorization: Bearer <token>`。

| 方法 | 地址 | 说明 |
| --- | --- | --- |
| POST | `/api/auth/login` | 用户名密码登录，返回 JWT 和角色 |
| POST | `/api/auth/register` | 注册客户账号 |
| POST | `/api/auth/logout` | 退出当前会话 |
| GET | `/api/auth/me` | 获取当前登录账号 |
| GET/POST | `/api/service-items` | 查询或维护服务项目 |
| GET | `/api/regions` | 查询启用服务区域 |
| GET/POST | `/api/demands` | 查询或提交客户服务需求 |
| POST | `/api/demands/{id}/approve` | 管理员审核需求并生成工单 |
| GET/PUT | `/api/work-orders`、`/api/work-orders/{id}/status` | 查询工单、变更合法状态 |
| GET/POST | `/api/scheduling/orders/{id}/candidates`、`.../assign` | 候选人员和派单 |
| GET/POST | `/api/service-process/orders/{id}` | 服务时间线和过程记录 |
| POST | `/api/reviews/orders/{id}/accept`、`/api/reviews/orders/{id}` | 验收与评价 |
| GET/POST/PUT | `/api/complaints` | 投诉创建与管理员处理 |
| GET | `/api/statistics/dashboard` | 统计看板数据 |
| PUT | `/api/work-orders/{orderId}/status` | 按状态机变更工单状态并写入历史 |

演示账号：`admin`、`customer01`、`provider01`，密码均为 `123456`。工单状态请求体示例：

```json
{"status":"IN_SERVICE","remark":"服务人员已开始服务"}
```

接口层只负责接收请求，状态合法性由 `WorkOrderStatusService` 统一校验，数据层使用 MyBatis-Plus/MyBatis 注解访问业务表。所有接口统一返回 `{code,message,data}`。
